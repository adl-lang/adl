# adl_rt

Runtime support for rust code generated by [adlc], the compiler for the
[Algebraic Data Language][adl].

You do not call this crate directly. adlc generates rust that refers to it, and
you add it to your `Cargo.toml` so that generated code compiles:

```toml
[dependencies]
adl_rt = "0.1"
```

It holds the few things generated code needs that the rust standard library
does not provide in an ADL compatible form:

- `ByteVector`, ADL's `Bytes`, serialized as base64.
- `Map`, `Set`, `Maybe`, `Pair` and `Result`, the custom mappings for ADL's
  `sys.types` declarations. Each wraps the obvious standard library type and
  gives it ADL's json encoding, which is not the one serde would choose. ADL's
  `Maybe`, for instance, is `{"just": v}` or `"nothing"`, not `v` or `null`.
- `AdlAnnotations`, re-exported from the companion [`adl_rt_derive`] crate. It
  is a derive macro, which is why it lives in a crate of its own, and is
  re-exported here so that generated code needs only this one dependency.

The module tree is also available without the crate: adlc's `--include-rt` flag
copies `src/` into a generated project as a plain module, which is how projects
predating this crate obtain it. The two are the same code, except that the
`AdlAnnotations` re-export exists only in the crate.
